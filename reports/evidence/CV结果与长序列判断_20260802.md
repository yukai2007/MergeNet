# MergeNet CV 结果与长序列判断（2026-08-02，08-03 效率更新）

> 汇报入口：[MergeNet on CV 阶段成果与 ImageNet 长训交付说明](../mergenet_cv_results_20260809.html)

## 一句话结论

> CIFAR-100 的结果在“机制与精度”上值得谨慎乐观，在“压缩配方的工程潜力”上出现了明显改善；但目前没有足够证据宣称 ImageNet 泛化、长序列高效或整体又快又省。

实现口径更新（2026-08-09）：历史 canonical `mergenet_small_cls` 的 LocalEncoder 使用 `LocalBlock`（unbiased attention）+ `DTEMMergeOnly`，不实例化 `DTEMAttention`。交付版对 biased FlashAttention 的 BHND/BNHD 与重复 scale 修复属于遗留 / 兼容路径加固，不使历史 canonical CIFAR 结果失效。ImageNet 仍需从头训练，是因为这是新的数据集、1000 类类别空间和训练尺度验证，而不是因为兼容路径修复改变了历史主模型前向语义。

## 1. 现有 CV 结果算不算乐观

| 维度 | 证据 | 判断 |
|---|---|---|
| 最佳精度 | `ld6/lat6, λ=2, w16`：seed 42/43/44 为 71.27 / 71.41 / 70.55，均值 `71.08±0.46` | 乐观：MergeNet 自身三 seed 方向稳定 |
| 对 DeiT | 同 seed 42、同 200 epochs、同 logit-KD：71.27 vs 68.52，`+2.75pp` | 有力信号，但 DeiT 只有一个 matched seed，不能说统计显著或全面胜出 |
| 对原始 ToMe | 同 seed 42、λ=4、logit-KD：MergeNet 69.67 或 70.93，ToMe-original 68.21，`+1.46～2.72pp`；no-KD 差值仅 `+0.38pp` | learned soft routing 有价值，但还需要 ToMe 多 seed 和 ImageNet |
| 高压缩 | `ld4/lat8, λ=4, w32` 保留 196/784 token，三 seed `70.60±0.43` | 很值得讲：75% latent token reduction 下只比 λ2 最佳均值低 0.48pp |
| 压缩曲线 | λ2/3/4：392/262/196 tokens，对应 71.08/70.37/69.79 | 规律清楚：压缩越强，精度平滑下降，不是偶然单点 |

最稳妥的汇报说法：

> CIFAR-100 已经证明 learned merging 不是随机技巧：多 seed 下有稳定精度收益，并形成可解释的压缩—精度曲线。下一步必须用 ImageNet 和真正长序列任务判断它是否是通用机制。

## 2. 效率结论已经比旧版更乐观，但尚未获胜

8 月 3 日将 DeiT、λ4 和 λ2 放在同一个任务中做了四卡干净配对 microbenchmark，以排除 8 月 2 日一次 DeiT 推理异常慢样本对比值的影响。最新结果是：

- 压缩优先 `ld4/lat8, λ4, w32`：训练吞吐为 DeiT 的 `91.3%`，推理吞吐为 `89.3%`（`1880 vs 2104 img/s`）；训练显存为 DeiT 的 `74.9%`，但推理显存仍为 `1.98×`。
- 准确率优先 `ld6/lat6, λ2`：训练/推理吞吐为 DeiT 的 `66.5% / 60.1%`，推理显存约 `2.18×`。
- random-per-sample 与 deterministic alternating 的训练吞吐只差 `1.27%`，所以“随机分组”不是主要效率瓶颈。主要成本来自 sort/gather/restore、soft merge 后仍保留全量 token，以及后续 cross-attention。

因此现在可以说：

> λ4 压缩配方已经接近 DeiT 吞吐，并在训练显存上转正；但当前实现仍未达到端到端又快又省，特别是推理显存仍需优化。

不能说 fast path 已经完成重新训练；目前证据是旧 checkpoint 的精度兼容和 microbenchmark。

## 3. 能不能推广到长序列

### 机制上可以，当前实现还不是 long-sequence ready

当前长度证据只有：

- 224×224、patch 8：`N=784`，这是主结果。
- 320×320、patch 8：`N=1,600`，单 seed 可以运行，但精度约 67.54。
- 旧 384×384 路线：`N=2,304`，MergeNet 72.88 vs DeiT 79.46，不能作为长序列优势。

复杂度上，local attention 和 DTEM 匹配可近似为 `O(N·w)`；但 local 阶段没有物理删除 token，Top-k 之后仍有：

- encode cross-attention：`O(KN)=O(N²/λ)`；
- latent self-attention：`O(K²)=O(N²/λ²)`。

所以当前架构只是把二次项缩小，并没有消除。要推广到 16k/64k 甚至更长序列，至少需要：

1. local 内尽早做真正的 physical compaction，而不是只搬运质量；
2. 把 full-patch cross-attention 改为 chunked、local、sparse 或 linear readback；
3. 对 1D 文本/DNA 使用严格相邻 routing 和相对位置，避免 CV 里 row-major 展平带来的行边界问题；
4. 报告 1k/4k/16k/64k 的吞吐、显存和 log-log scaling slope；
5. 先做 copy / associative recall / needle 等机制任务，再做 hg38 next-base 和 NT/GUE。

推荐口径：

> CV 已证明“先局部理解、再按内容压缩”的机制有潜力；能否成为长序列模型，取决于能否把现在的后置 Top-k 变成更早的物理压缩，并把 `K×N` readback 从二次复杂度改掉。

## 4. 新可视化应该怎样解释

原始 ToMe 的 source visualization 展示的是 final token 对初始 patch 的硬 membership，不是 saliency；destination 也只是二分匹配的保留端，并不是“重要 token”。参考：[ToMe paper](https://arxiv.org/pdf/2210.09461)、[official visualization notebook](https://github.com/facebookresearch/ToMe/blob/main/examples/2_visualization_timm.ipynb)、[official source tracing](https://github.com/facebookresearch/ToMe/blob/main/tome/merge.py)。

MergeNet 新图使用更符合本模型的三段语义：

1. 箭头：实际 DTEM donor→receiver 的 fractional mass transport；
2. 星号：最终被 Top-k 保留的 high-mass representative；
3. 最后一列：代表 token 通过 encode cross-attention 回看哪些完整 patch keys。

图中不要写“模型发现了语义最重要 token”，应写：

> 局部质量在 soft routing 中向部分 token 槽聚集，高质量代表被 Top-k 保留；代表随后通过 cross-attention 回看全量 patch。颜色表示被动追踪的来源质量，不是语义分割或类别归因。

特别注意：当前 `dtem_window_size=8` 是 row-major 展平索引上的 `±8`，不是二维 `8×8` 邻域。新图出现横向 source strip 正是这一实现事实的可视化。交付 v1 为了只检验 scale-up、避免同时改变 grouping 几何，保留这一路径；ImageNet 224/p8 与历史 CIFAR-resize 同为 28×28 patch grid，因此它不是启动门槛，但仍是后续应以二维邻域或显式行边界解决的科学限制。
