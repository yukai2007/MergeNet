# MergeNet on CV 交付证据索引

> 审计截止：2026-08-03；交付整理：2026-08-09。本文只保留本次 CV 汇报所需的可移植摘要。原始 checkpoint、逐步日志和 benchmark JSON 因体积与机器路径原因不进入 Git 交付包。

> 汇报入口：[MergeNet on CV 阶段成果与 ImageNet 长训交付说明](../mergenet_cv_results_20260809.html)

## 1. 可交付结论

- 现有 CIFAR-100 证据足以支持进入 ImageNet-1K 大规模验证，不等于 ImageNet 已完成验证。
- 精度优先配置：MergeNet 6+6、λ=2、window=16，3 seeds Top-1 为 `71.08 ± 0.46`。
- 压缩优先配置：MergeNet 4+8、λ=4、window=32，3 seeds Top-1 为 `70.60 ± 0.43`，latent encoder 仅保留 `196 / 784` patch tokens。
- λ=4 fast 微基准的训练峰值 allocated memory 为 DeiT 的约 `0.749×`；推理吞吐约 `0.893×`，但推理显存约 `1.983×`，因此不能表述为端到端全面优于 DeiT。
- 主准确率训练与 fast 训练微基准不是联合验证的同一配置，必须分别陈述。
- 历史 canonical `mergenet_small_cls` 使用 `LocalBlock`（unbiased attention）+ `DTEMMergeOnly`，不实例化 `DTEMAttention`；biased-attention 修复是兼容路径加固，不使历史 canonical CIFAR 结果失效。
- ImageNet 必须从头训练，是因为数据集、1000 类类别空间和训练尺度均为新的 scale-up 验证；当前没有 ImageNet 精度结果。

## 2. CIFAR-100 主准确率证据

共同协议：scratch 200 epochs、输入 224、patch size 8、global batch 200、AdamW、warmup 20 + cosine、Mixup/CutMix/RandAugment/random erasing、EMA、logit KD。准确率训练使用 `random_per_sample`，验证使用 `alternating_per_layer`。

| 配置 | seed 42 | seed 43 | seed 44 | mean ± sample SD | latent patch tokens |
|---|---:|---:|---:|---:|---:|
| MergeNet 6+6 / λ2 / w16 | 71.27 | 71.41 | 70.55 | **71.08 ± 0.46** | 392 / 784 |
| MergeNet 4+8 / λ4 / w32 | 70.93 | 70.11 | 70.76 | **70.60 ± 0.43** | 196 / 784 |
| DeiT-S/8 / logit KD | 68.52 | 未跑 | 未跑 | 单 seed | 784 / 784 |

同 seed 42、同 logit-KD 协议下，λ2 相对 DeiT 为 `+2.75 pp`，λ4/w32 为 `+2.41 pp`。由于 DeiT 只有 seed 42，这不是统计显著性结论。

辅助控制：无 KD 的单 seed 实验中，MergeNet 6+6 / λ4 为 `69.24`，DeiT 为 `66.53`（`+2.71 pp`）；该结果支持增益不只来自 teacher，但仍需补多 seed。

## 3. Clean efficiency 证据

协议：4 张 A100-SXM4-80GB 分别独立运行，PyTorch 2.6.0 + CUDA 12.4，FP16，batch 50，20 steps warmup + 100 measured steps；训练项包含 student forward、CE、backward 和 AdamW，不含 dataloader、增强和 teacher。

| 配置 | train img/s | train peak allocated | infer img/s | infer peak allocated | params |
|---|---:|---:|---:|---:|---:|
| DeiT-S/8 | 543.75 | 6902.8 MiB | 2104.02 | 628.7 MiB | 21,708,772 |
| MergeNet 4+8 / λ4 / w32 fast | 496.32 (`0.913×`) | 5170.8 MiB (`0.749×`) | 1879.91 (`0.893×`) | 1246.7 MiB (`1.983×`) | 22,701,284 |
| MergeNet 6+6 / λ2 / w16 fast | 361.37 (`0.665×`) | 7307.8 MiB (`1.059×`) | 1264.66 (`0.601×`) | 1368.1 MiB (`2.176×`) | 22,750,564 |

表中参数量对应 CIFAR-100 分类头。交付包换为 1000 类 ImageNet head 后，模型工厂实测参数量为 DeiT `22,055,272`、λ4 `23,047,784`、λ2 `23,097,064`；差值来自分类头类别数，不是架构数据冲突。

λ4 fast train 四卡吞吐为 `444.90 / 511.17 / 518.46 / 510.75 img/s`，逐卡相对 DeiT 为 `0.820 / 0.961 / 0.942 / 0.928×`，样本 CV 为 `6.94%`。均值受到 GPU0 低值影响，交付机器必须复跑；显存比和推理吞吐相对稳定。

fast inference 已用历史 checkpoint 做全测试集 replay：λ4/w32 seed 42 的 generic 与 fast Top-1 均为 70.91，逐样本预测一致率 1.0000；λ2 三 seeds 最大 Top-1 差 0.01 pp，预测一致率至少 0.9998。

## 4. 必须保留的证据边界

1. `71.08 / 70.60` 来自 `random_per_sample` 长训；`0.913×` train microbench 来自 `alternating_per_layer_fast`，后者没有对应 200e 长训。
2. token 数减少是 latent encoder 输入压缩，不等于端到端 FLOPs 同比例下降；当前未提供经审计的 FLOPs。
3. CIFAR 实验每 epoch 在 test split 上评估并选 best，内部比较可用，但论文版应改为 train/validation 选 checkpoint，最后只测一次 test。ImageNet 交付按 train/val 执行。
4. 遗留 / 兼容 `DTEMAttention` 路径存在 BHND/BNHD 布局与重复 scale 风险，交付版已修复并加入 parity 回归门禁。canonical `mergenet_small_cls` 走 `LocalBlock`（unbiased attention）+ `DTEMMergeOnly`，不调用该路径，因此不能将兼容路径缺陷解释为历史主结果失效。ImageNet fresh train 的原因是新数据集 / 新类别空间 / 新训练尺度，而不是修复后必须重现 CIFAR。
5. `dtem_window_size=8` 是 row-major 展平序列上的 ±8，不是二维 8×8 邻域；224/p8 的 ImageNet 与历史 CIFAR-resize 具有相同 28×28 patch grid，但该几何限制仍应在后续工作中解决。
6. λ4 fast 推理显存约为 DeiT 的 2 倍，不能声称“推理更省显存”或“生产效率全面领先”。
